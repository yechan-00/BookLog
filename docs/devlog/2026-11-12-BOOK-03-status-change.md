## 1. Summary

책 상세에서 독서 상태를 직접 바꿀 수 있게 하고, 상태 변경과 집중 독서(타이머)를 분리했다. 읽는 중인 책은 읽고 싶음으로 바로 되돌릴 수 없고 임시 중단 또는 완독을 거쳐야 한다. 읽고 싶음·임시 중단 책으로 집중 독서를 시작하면 "읽는 중으로 바뀐다"는 확인을 먼저 받는다.

## 2. Requirements

- BOOK-03: 상태 변경 API와 책 상세 UI 구현. 서재 탭의 상태 변경·중단 탭은 한예찬 몫이라 남아 있다 (진행 중)
- PRD와 다른 점: PRD는 "완독한 책 다시 읽기는 MVP에서 지원하지 않는다"였지만, 완독 → 읽고 싶음으로 되돌려 다시 시작하는 것을 허용하기로 해 수용 기준을 바꿨다. 팀(한예찬) 확인이 필요하다.

## 3. Implementation

- `utils/bookStatus.ts`: 전환 표. 읽고 싶음 → 읽는 중 / 읽는 중 → 임시 중단·완독 / 임시 중단 → 읽는 중·읽고 싶음·완독 / 완독 → 읽고 싶음.
- `lib/api/books.ts` `updateBookStatus(userBookId, from, to)`: 완독은 리뷰가 필요해서 `completeBook`으로만 하고 여기서는 거부한다. 저장된 상태가 `from`과 다르면(다른 화면에서 이미 바뀜) 거부하고 갱신도 `status = from` 조건을 걸어 덮어쓰지 않는다. 읽는 중으로 바꿀 때 시작일이 비어 있으면 오늘로 채운다. 완독 → 읽고 싶음은 진행률 0, 시작일·완독일 삭제(지난 세션과 인덱스는 유지).
- `app/book/[id].tsx`: 현재 상태에서 갈 수 있는 상태만 칩으로 보여 준다(읽는 중에서는 읽고 싶음 칩이 없고 안내 문구가 나온다). 완독 칩은 완독 처리 화면으로 이동한다. 진행 중인 독서가 있는 책은 상태를 바꿀 수 없다. 완독 → 읽고 싶음은 확인을 받는다. 같은 일을 하던 "완독하기" 버튼은 칩과 중복되어 없앴다.
- `lib/reading/startReading.ts`: 세 번째 인자 `status`를 선택으로 받는다. 읽고 싶음·임시 중단이면 확인 Alert를 띄우고, 이미 진행 중인 세션을 이어하는 경우와 읽는 중인 책(홈의 이어 읽기 카드 등, 인자 없음)은 묻지 않는다. 기존 호출은 그대로 동작한다.
- 책 상세의 버튼 이름을 "독서 시작"에서 "집중 독서 시작"으로 바꿨다.
- 상태가 실제로 바뀌는 시점은 세션을 저장할 때다(`finish_session`). 시작만 하고 기록 없이 종료하면 상태는 그대로다.

## 4. Problems & Solutions

- 전환 규칙을 DB에서 강제하지 못했다. 트리거가 필요한데, 검증 환경(로컬 Docker)이 없어 원격 DB에 올리지 않았다. 지금은 앱 코드에서만 막으므로, 다른 경로로 직접 갱신하면 규칙을 우회할 수 있다.
- 완독 → 읽고 싶음에서 진행률을 되돌리지 않으면 다음 세션의 시작 페이지가 총 페이지가 되어 읽을 수 없다. 그래서 0으로 초기화한다.

## 5. Verification

- `npx tsc --noEmit`, `npx expo lint` 통과
- 원격 DB에서 새로 등록한 책 한 권으로 같은 전환 로직을 확인함 (통과): 읽고 싶음 → 읽는 중(시작일 기록), 읽는 중 → 읽고 싶음 차단, 읽는 중 → 완독 차단, 임시 중단, 오래된 화면의 `from` 거부, 임시 중단 → 읽고 싶음, 다시 읽는 중에서도 최초 시작일 유지, 완독 → 읽는 중 차단, 완독 → 읽고 싶음 초기화. 시험한 행은 지웠고 팀원 데이터는 그대로다.
- 같은 시험에서 `complete_book` 쓰기도 확인됐다(READ-05 DevLog에서는 미확인으로 적었다): 상태 완독, 완독일 기록, 현재 페이지 = 총 페이지.
- 확인하지 못함: 앱 화면(칩, 확인 Alert, 진행 중 독서 차단). Android 실기기에서 확인해야 한다.
